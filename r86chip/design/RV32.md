# RV32 ISS and firmware execution

The [Rust ISS](../sim/rv32.rs), selected with `Core::new`, is the executable
gold standard. See the [ISA source index](ISA.md) for decoding, architectural
state and behavior tests. ISA changes start in this model before Chisel;
private encodings and firmware ABIs need not remain backward compatible.

## Current same-core path

The [machine runner](../sim/machine.rs) loads an RV32 ELF and executes its actual
machine words using the current ISS. The firmware runs the shared x86
interpreter, PC devices and optional B1 translator on this simulated core.
Generated code also executes through the same instruction interpreter.

- [machine.rs](../firmware/machine.rs) and
  [machine_runtime.rs](../firmware/machine_runtime.rs): firmware entry and PC runtime.
- [machine_abi.rs](../firmware/machine_abi.rs): memory layout and harness observations.
- [jit/runtime.rs](../jit/runtime.rs): translation dispatch, hotness and invalidation.
- [jit/compile.rs](../jit/compile.rs): emitted code and runtime frame.
- [TINYCORE.md](../experiments/TINYCORE.md): build/run commands and full boot gates.
- [B1_JIT.md](../experiments/B1_JIT.md): current translator coverage and comparisons.

From the repository root, build the ISS with:

```sh
cargo build --release --no-default-features --features r86chip --bin r86chip-sim
```

Its large-RAM entry is:

```text
r86chip-sim machine FIRMWARE.elf IMAGE_DIRECTORY RV_INSTRUCTION_LIMIT WALL_SECONDS
```

Use `tinycore.py --engine iss` to prepare firmware and images, or
`--engine rtl` to run the corresponding Chisel implementation under Verilator.
The Rust model establishes functional behavior; hardware cycles, fit and timing
require the RTL and synthesis checks in [RTL.md](RTL.md).

The native RTL suite also uses `r86chip-sim native RAM_IMAGE.bin` to compare
initialized registers, trap state and all RAM with the gold ISS at PC 0x1000.
The older demo/hex/packet-firmware commands have been removed.
