# Playbook: install and verify the Thumb-2 JIT backend (`t32`)

For the Intern. Written by the Lead on 2026-11-14 against commit `f0f4acb`.

**What this does.** It adds `src/x86/jit/t32/`, an i386 to Thumb-2 JIT for
Armv8-M Mainline cores (Cortex-M33 class), selected by the new Cargo feature
`jit-t32`. Without the feature nothing changes.

**You do not write Rust.** The code is staged in `cortex-m/stage/` and was
already built and tested by the Lead. Four source files are copied, three are
generated by a script from the ARMv6K backend, and two small scripts edit
`Cargo.toml`, `src/x86/jit/mod.rs` and `design/VALIDATION.md`. Your job is to
run the commands in order, compare each result with the expected one, and stop
when they differ.

**Dry run.** The Lead ran every command below on a clean export of `f0f4acb`
(rustc 1.95.0, QEMU 10.0.13). All checks passed; section 3 quotes the outputs.

Run every command from `/work/r86`. Nothing here changes Git state.

### 1.2 Boundaries that must stay true

If any step would break one of these, stop; do not look for a way around it.

1. **Selection.** The backend exists only under `feature = "jit-t32"`. With
   the feature on a 32-bit ARM target, `crate::x86::jit::runtime` is
   `t32::runtime`; `machine.rs` needs no change because the engine has the
   same interface (`new`, `clear`, `report`, `run_batch`, field `stats`).
2. **Self-contained.** `t32` imports nothing from `arm32`. It shares only
   `jit::decode`, `jit::compile::{STATUS, flag_requirements}` and the `Cpu` and
   `HostBus` hooks the ARMv6K runtime already uses.
3. **Data flow.** One invocation is `Cpu` → `Frame` → native code → `Frame` →
   `Cpu`. Generated code touches only the `Frame`, software-TLB rows and guest
   RAM reached through a write-tag hit.
4. **Precise exits.** An instruction that cannot finish natively leaves
   before it starts, with complete flags, and the interpreter runs it.
5. **Thumb bit.** Every code address given to native code (entry, block,
   dispatcher, miss stub, table entries) has bit 0 set. `Arena::publish`
   returns even addresses.
6. **Types.** Code is `Vec<u16>` halfwords. `Assembler::offset`,
   `Shared::dispatch` and `Shared::miss` count halfwords (multiply by 2, never
   by 4).
7. **Encodings.** Base Armv8-M Mainline T32 only: operands R0-R12 and LR, SP
   only through PUSH and POP, no DSP, floating-point or coprocessor words.
8. **Guest time.** Both engines retire the same instruction count. The boot
   check compares it.
9. **Performance.** Nothing on the interpreter path changes.

## Appendix A. What the code is (background, not instructions)

- **Layout.** `asm.rs` 970 lines, `lower.rs` 1,875, `runtime.rs` 639,
  `store.rs` 201, `arena.rs` 142, `tests.rs` 522, `mod.rs` 32.
- **Registers.** R4-R11 hold EAX-EDI. LR points to the `Frame`. R0-R3 and
  R12 are scratch; a memory guard uses R2, R3, R12 and leaves the host bias in
  R3. SP is used only by the entry PUSH and the exit POP, so an interrupt
  always finds a valid stack.
- **Frame** (96 bytes): `regs` 0, `eip` 32, `nzcv` 36, `result` 40,
  `auxiliary` 44, `eflags` 48, `exit` 52, `remaining` 56, `table` 60,
  `tlb_state` 64, `tlb` 68, `dispatch` 72, `based` 76, `bases` 80,
  `limits` 88. `shared_stub_matches_reference` pins the offsets.
- **Flags.** APSR N/Z/C/V carry x86 SF/ZF/CF/OF between instructions of a
  block; the lowering tracks whether C is CF or its inverse. They are stored
  to the frame before any instruction that can leave. PF and AF come from
  `result` and `auxiliary`.
- **Memory.** Each access checks one software-TLB row (16 bytes: bias, read
  tag, write tag) for the first and last byte's page. A miss leaves before
  the instruction. Write tags never cover watched code pages, so native code
  cannot change compiled bytes.
- **Dispatch.** A block reserves its instruction count from
  `Frame.remaining`. A static target probes its dispatch-table slot inline;
  other targets go through the dispatcher. A miss returns to Rust.
- **Runtime.** Blocks are keyed by (EIP, flat-segment facts, backing byte),
  admitted on the sixteenth visit, kept in a four-way table of 32,768 records,
  and revalidated by comparing their source bytes when their page's version
  changes.
- **Different from the ARMv6K backend.**
  1. Encoder: T32, MOVW/MOVT constants (no literal pool, so compilation
     cannot fail on reach), IT blocks of one instruction, BFI/BFC for partial
     registers, register-count shifts as separate instructions.
  2. Division: 32-bit DIV/IDIV run natively with UDIV/SDIV when EDX is the
     zero or sign extension of EAX; other cases leave to the interpreter.
  3. Block index: a fixed table (`store.rs`) instead of a growing hash map;
     source bytes live in the code arena.
  4. Dispatch miss: when the target already has a valid record, `invoke`
     re-enters native code from the same frame (`Stats::resolved`) instead of
     unwinding to `run_batch`.
  5. Code memory: Linux `mmap`, or two functions a bare-metal port defines
     (`r86_t32_code_region`, `r86_t32_code_publish`).

## Appendix C. Deliberately not in this change

Each needs its own plan and, for the first three, a device to measure on.

1. **Refilling a TLB row without leaving native code.** The shared helper
   (`mmu::try_resident_data_translation`) is not compiled for 32-bit ARM and
   has its own recheck protocol.
2. **Direct links between blocks.** One native entry per 80 guest
   instructions remains; links would remove most table probes but need an
   unlink rule for every way a block can become invalid.
3. **16-bit encodings** for denser code, and table, arena and block-index
   sizes for a device with a few megabytes of RAM. The constants are those of
   the ARMv6K backend, except `BLOCKS`.
